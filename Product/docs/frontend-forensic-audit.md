# Frontend Forensic Audit

## Scope

This audit was created for `M-FRONTEND-PRODUCTION-REDESIGN-1` after the browser screenshots from `v1.19.6-product-quality-visual-story-reset-1` showed that the previous product-quality reset was technically complete but still visually unacceptable.

Audited areas:

- `src/App.tsx`
- `src/routes/Play.tsx`
- `src/routes/Mirror.tsx`
- `src/routes/Progress.tsx`
- `src/routes/Story.tsx`
- `src/routes/ClueChess.tsx`
- `src/routes/AnalyticsDashboard.tsx`
- `src/routes/GameReview.tsx`
- `src/routes/PgnImport.tsx`
- `src/components/Board/BoardView.tsx`
- `src/styles/designSystem.css`
- browser screenshots generated under `artifacts/frontend-redesign/`

## User-Reported Screenshot Failure

On `/play` at a normal desktop width:

- the chessboard overlapped the match/control panel
- match information was hidden behind the board
- "Analyze Game" and "Open Game Review Pro" collapsed into narrow vertical fragments
- local match history bled into the board area
- navigation looked crowded and prototype-like
- the route did not feel premium, immersive, or market-grade
- the prior visual QA passed despite visible layout collisions

## Root Causes

### App Shell

The previous `App.tsx` owned the header, navigation, route container, theme controls, and audio controls inline. Primary product routes, secondary tools, and system diagnostics competed in the same visual space. The header had no clear hierarchy, and route content relied on route-local spacing to avoid collisions.

Risk level: high. The shell affected every route.

### Navigation

Navigation presented core game modes, utility pages, account/project pages, and diagnostics as similar links. At narrower widths, wrapping was uncontrolled, making the UI feel like a debug link list rather than a product.

Risk level: high. Navigation was visible everywhere and created first-impression quality issues.

### `/play`

The Play route mixed board stage, match controls, review actions, and local history without a stable three-region grid. The board width was partly viewport-driven, so at some desktop widths the board could outgrow the center column and visually collide with the right panel. The history table did not have a strict card-contained overflow contract, and review actions could shrink until labels wrapped into unreadable fragments.

Risk level: critical. `/play` is the primary product screen.

### Board Sizing

`BoardView` resized from its parent observer but had no shared route-level layout contract. The board itself was valid, but parent routes could give it a container that was too narrow or unstable. The theme frame and board labels also needed stricter containment.

Risk level: high. Board layout affects Play, Mirror, Clue Chess, Story, and Review.

### `/progress`

The profile/progress route still looked closer to raw application state than a polished player dashboard. It had weak hierarchy, loose spacing, and default-feeling actions. Direct navigation could also briefly lack an active player before the persisted player store finished loading.

Risk level: high. Profile is a recruiter-visible and player-facing surface.

### Tables and Long Content

Route tables and PGN/review text areas were not consistently wrapped in overflow-aware cards. Long rows and action groups could push outside their parent region.

Risk level: medium-high. This caused visible bleeding in history and import/review screens.

### QA Gap

The previous product-quality script checked route loading and basic behavior. It did not save screenshots across required viewports, inspect primary-region bounding boxes, or fail when body width exceeded viewport width. As a result, visible overlap could pass automated QA.

Risk level: critical. QA gave false confidence.

## Remediation Plan

Completed in this milestone:

- Introduce a shared app shell with `AppHeader`, `AppNav`, and route-safe `PageFrame`.
- Split navigation into primary product modes, secondary tools, and system diagnostics.
- Add reusable UI primitives for buttons, cards, panels, badges, metrics, segmented controls, action links, empty states, and table cards.
- Rebuild `/play` as an explicit responsive grid with controls, board stage, and history/review panels.
- Constrain board sizing to the route column instead of the viewport alone.
- Rebuild `/progress` as a polished profile page with hero, metrics, XP progress, recent activity, training actions, and backup card.
- Wrap tables and long content in card-contained overflow regions.
- Update `run-product-quality-visual-check.mjs` to use the new screenshot and bounding-box QA.
- Add `run-frontend-production-redesign-check.mjs` to test real browser screenshots at 1440x900, 1366x768, 1280x720, 1024x768, 900x768, and 390x844.

## Screenshot Evidence

Screenshots are generated by:

```bash
node scripts/run-frontend-production-redesign-check.mjs
```

Artifact folder:

```text
Product/artifacts/frontend-redesign/
```

Manual review after the rebuild confirmed:

- `/play` no longer overlaps controls, board, and history at desktop widths.
- `/play` mobile stacks into one readable column.
- review actions remain readable buttons instead of vertical text fragments.
- match history remains inside its card.
- `/progress` no longer presents raw Back Home/default backup controls.
- navigation is grouped and visually separated from system diagnostics.

## Remaining Risks

- The 2D Kurukshetra theme is still a placeholder, not realistic 3D.
- Some older feature routes still carry local legacy classes, but they now live inside the shared shell and receive design-system overrides.
- Future route additions must use shared components and screenshot/bounding-box QA before tagging.
